# Jupiter conformance and exceptions

Show Player uses WinUI 3/C# with a Rust domain core, narrow generated protobuf C ABI and shared Jupiter.UI resources. The style check runs as an error on every build. It uses the standard Windows title bar, player workspace, collection panes, shared theme/accent controls and a self-contained Inno Setup installer with a Start Menu entry.

The show workshop is an owned secondary suite window, keeping listening available independently of import/download tasks. It uses standard 224/48 navigation widths and collection/detail regions. Its minimum size is 1000 × 640 effective pixels rather than 800 × 560: the navigation, editable track list and metadata inspector need that width. The initial workshop inspector is fixed at the standard 320-pixel width rather than resizable; its import content scrolls. The player library pane retains its splitter. Workshop pane resizing is follow-up work. These are recorded layout exceptions, not a replacement visual system.

The unsaved metadata review draft is a C# projection of the Rust inspection result. It is submitted in a typed protobuf request and validated again in Rust before packaging. Persisted playback state remains Rust-owned. Draft persistence is not implemented.

As of 0.2.2, FFmpeg/ffprobe are the only bundled process adapters, used for local inspection and MKA creation under Rust. Arguments are passed directly without a shell; child processes are hidden, logs are surfaced in the workshop, and cancellation terminates and waits for the child. The network downloader and aria2 have been removed. libmpv remains an in-process playback dependency.

29 October 2026 (release 0.2.1): `SourceBadgesControl` uses a recording-content palette (style standard 3.4 / JUP001): blue SBD, purple MTX, ochre AUD and teal modifiers, with white labels. Colors identify content type, never quality or selection. The same opaque palette is used in light and dark appearances because its white-on-fill contrast is independent of the surrounding surface. UNKNOWN uses Jupiter neutral tokens. Contrast themes replace every badge with Jupiter system-mapped foreground/background/border tokens; text always carries the full source code. Literal colors are locally marked `jupiter-allow JUP001` in XAML. No Jupiter or WinUI resource keys are replaced.

30 October 2026 (release 0.3.0): standard 3.3 says no app ships with a different default accent. Gratitude departs from it in one case. Selection tints and primary actions take the accent, and on a recording list a red tint reads as an error or warning. When the Windows accent has a hue from 285 to 40 degrees and is not close to gray, `AppSettings.AvoidRedAccent` stores `#2E7D9A` once as the app's custom accent, through the shared `AccentService` preferences. Settings > Appearance > Accent color still offers **Reset to Windows accent**, and that choice is kept. Any other Windows accent is followed as usual. The Windows title bar stays under Windows control and keeps the system accent if the person has turned that on.
